01 / HADOOP

Introduction

Apache Hadoop is an open-source software framework for storing and processing large datasets across a cluster (connected computers that cooperate). Hadoop is the software; the cluster supplies the machines, storage and network.

We will follow one problem throughout this chapter: count how often each search term appears in text files exported by a university website. The lab uses two tiny files so that every intermediate result can be checked by hand. The same division of responsibilities applies to much larger datasets.

Place the systemPurpose, ecosystem and architecture Understand its partsStorage, resources and computation Build the small versionOne computer, the same service roles Run and explain itTrace the data and verify the result

Why use several computers?

A single machine has finite disk space, memory and processing capacity. More machines can store more data and process independent portions at the same time. The cost is extra communication and coordination: adding machines does not automatically make every job faster.

Distributed storage

Keep different portions of a file on several machines.

Parallel computation

Work on several input portions at the same time.

Fault tolerance

Recover from eligible failures using data copies and new execution attempts.

Split the storage, keep one file

A block is a chunk of file bytes that the storage system manages separately. A worker is a participating machine that stores data, runs computation, or both.

Split the computation, answer one question

A job is one submitted computation. A task is a portion of that job's work. A batch job processes a collected dataset and produces results; our example counts words in stored text files.

Keep data available and work recoverable

A replica is another stored copy of the same block. Replication creates these copies; a retry runs another attempt of failed work. Together they support fault tolerance: the ability to keep working despite certain failures.

If this fails…The system needs…Responsibility
A machine holding a data blockA readable replica on another machineHDFS storage
A computation taskA new attempt with accessible inputMapReduce processing

Replication does not complete failed calculations, and retrying cannot recreate missing input with no surviving copy. We will trace both mechanisms separately.

Where Hadoop fits

Hadoop is useful for large batch scans and transformations, such as historical reports and log analysis. Job startup and data exchange have costs. Small local datasets and individual low-latency database updates often call for different tools.

02 / HADOOP

The Hadoop ecosystem

Where does Hadoop belong in a complete data platform?

A real data platform is more than a storage system or a computation engine. It must collect data, retain it, execute processing, and make the results available. The Hadoop ecosystem refers to Hadoop's core modules together with separate tools that can complement them. An ecosystem is not a single executable, and a deployment does not need every related project.

Follow a dataset through the platform

The university website exports search terms into text files. Every night, we want a frequency report: how many times did each word occur? Our WordCount job answers this question. The five-word lab dataset is a small, inspectable version of this batch workflow.

The important distinction is that the text moves from storage to computation and the result returns to storage, whereas requests for computation resources are handled separately. The same HDFS data can later be processed again without collecting the search terms again.

03 / HADOOP

System architecture

Which processes do the work, and which machines host them?

A software module is a set of related functionality; a running system needs processes that carry it out. A node is a participating machine or execution host; a daemon is a long-running service process. One machine may run several daemons, and a Hadoop application may launch temporary processes on different workers.

Introduce the service names

ModuleControl serviceService on a worker
HDFSNameNode: tracks file paths, permissions and block locations. This information is called metadata.DataNode: stores block bytes and serves reads and writes.
YARNResourceManager: allocates CPU and memory across applications.NodeManager: starts and monitors application processes on its machine.

A client is a program using these services, such as an HDFS command or a job submission tool. Each submitted MapReduce job has an ApplicationMaster, a temporary coordinator for that job. YARN provides containers: resource allocations, such as CPU and memory, in which application processes execute.

A map task reads an assigned portion of the input and emits intermediate results. A reduce task aggregates results belonging together. The MapReduce section will show their exact inputs and outputs.

A typical multi-node cluster

The NameNode and ResourceManager are different control services. A NameNode maintains file metadata and current block locations; it does not allocate CPU to a mapper. A ResourceManager decides resource allocations; it does not maintain the file block map. Each worker's DataNode serves stored bytes, and its NodeManager launches and monitors application containers.

MapReduce defines and organises the job. It is not a fifth permanent daemon in our lab. Its ApplicationMaster and task attempts appear when the job runs. An optional JobHistoryServer can provide information about completed MapReduce jobs.

04 / HADOOP

HDFS

The architecture separates stored data from the services that coordinate it. Follow an input file through the storage part of that system.

HDFS (Hadoop Distributed File System) stores files in blocks, byte ranges that can reside on different machines. A replica is another copy of the same block. Applications use one file path even when several DataNodes hold its contents.

ParticipantResponsibility
NameNodeMaintains metadata: filenames, directories, permissions, and the mapping from files to blocks and block locations.
DataNodeStores block contents on its disks and serves reads and writes.
ClientThe command or application using HDFS. It asks the NameNode for metadata and transfers file contents with DataNodes.

This separation lets many clients transfer data without sending every file byte through the NameNode. See the official HDFS architecture.

Read: locate the blocks, then fetch their bytes

Write: obtain destinations, then stream the block

A pipeline is an ordered chain that forwards data from one participant to the next.

Replication: availability first, replacement copies next

The replication factor is the target number of copies of each block. A factor of 2 means two copies in total on distinct DataNodes. Consider three blocks, B1–B3, and a spare DataNode D with enough space and a location permitted by the placement policy.

A heartbeat is a periodic message indicating that a DataNode is alive. A block report lists the blocks it stores. These serve different purposes: failure detection and knowledge of block placement. Replication protects against some storage failures; it does not undo an accidental file deletion.

Relating the model to our lab
A 300 MiB file with a nominal 128 MiB block size uses 128, 128 and 44 MiB blocks before replication and overhead; the final partial block is not padded to 128 MiB. Our lab has one DataNode and replication factor 1, so it cannot demonstrate survival of a DataNode failure.

HDFS now supplies readable input. YARN provides resources to process it; later, HDFS in practice lets you inspect files, blocks and their locations.

05 / HADOOP

YARN

HDFS answers where the input bytes live. The next question is where the processing can run and how much CPU and memory it can use.

YARN (Yet Another Resource Negotiator) manages cluster resources and application execution. An application is a submitted computation; in this lesson it is one MapReduce job. A task is a piece of that job, and a task attempt is one execution of the task.

ComponentScope and responsibility
ResourceManager (RM)Cluster-wide service that allocates resources across applications.
NodeManager (NM)Service on a worker that launches and monitors containers and reports resource use.
ApplicationMaster (AM)Coordinator for one application. The MapReduce AM requests resources, tracks tasks and handles task recovery.
ContainerAn allocation of resources, such as memory and CPU, on a worker, used to run an application process. It need not be a Docker container.

The distinction between cluster resource allocation and application coordination is described in the official YARN architecture.

Start the coordinator, negotiate resources, launch work

Task count and simultaneous execution differ

A job can contain more tasks than the available resources can run at once. In this separate three-task example, capacity fits two task containers; the AM's own resources are excluded from the count.

Data locality: prefer execution near the input

Data locality means placing computation near the bytes it needs. The AM can request a worker holding an input replica. If suitable resources are unavailable there, a task may run elsewhere and read over the network.

Recovery: run a new attempt of the same task

We can now store input and run task processes. MapReduce defines what those tasks do and how their partial results become one report.

06 / HADOOP

MapReduce

HDFS provides storage; YARN provides execution resources. MapReduce supplies the processing model for our nightly search-term frequency report.

MapReduce processes batches of input through map and reduce functions. A job is one complete computation with input, processing code and output. A task performs one part: a map task transforms an input portion; a reduce task combines the groups assigned to it.

A record is one unit presented to a processing function. MapReduce represents records as key–value pairs: a key identifies or groups something, and a value carries associated data. For text input, a record is a line: its key is its byte offset (the line’s starting position, measured in bytes from the beginning of the file), and its value is the line text. WordCount changes that representation to (word, 1). A mapper transforms input records; a reducer processes each assigned key and its grouped values.

Blocks, splits and records answer different questions

An InputFormat defines how to divide and read input. It creates InputSplit descriptions, each assigned to one map task, and supplies a RecordReader that turns input bytes into records. A split describes work; it is not a new stored copy of the data. See Apache's job input documentation.

What if a line crosses a block or split boundary?

HDFS stores bytes without understanding lines. Suppose a boundary falls inside the line data hadoop:

For ordinary uncompressed text, if a split boundary also falls inside this line, the responsible reader reads beyond its nominal split end to finish the record. The next reader skips the incomplete starting fragment. The boundary does not make the mapper count half a line or count it twice.

WordCount: the whole route remains visible

Our two files contain five search terms in total. Assume ordinary text input, one split per small file and one reducer. There is no combiner, an optional local aggregation step that can reduce the amount of intermediate data transferred.

The mapper splits each line into tokens, here words separated by whitespace. A partition is the portion of map output assigned to one reducer. The shuffle transfers those partitions from map workers to their destinations.

Select a phase to inspect the intermediate records. All counts are from the same five input words.

Map: independent input becomes a common representation

Each mapper tokenises its own lines and emits one pair per word. It does not need the other mapper's input. Both use the same output key and value types, so their pairs can be grouped together downstream.

Shuffle and sort: equal keys must meet

The partitioning rule must send equal keys to the same reducer. During the shuffle, each reducer fetches its partitions from the map workers; sorting and merging bring the values for each key together.

Reduce: one total per word

The reducer receives one key and its values, then emits their sum. For this input the result is data → 1, hadoop → 2 and spark → 2. One reducer produces one result part file, sorted by key here. Several reducers produce separate part files; a global ordering across those files is not generally guaranteed.

Persistent data and intermediate data have different lifetimes

Java WordCount

Our Hadoop MapReduce program has a Mapper, a Reducer and a Driver (the client-side code that configures and submits the job). The Mapper and Reducer define the computation. A JAR is a Java archive containing the compiled application classes; the Driver identifies the JAR so the workers can obtain the code.

1. Implement the Mapper

Each text input record is a pair consisting of the byte offset of a line (LongWritable) and the line content (Text). The mapper emits pairs with a word (Text) and a count of one (IntWritable).

Writable types tell Hadoop how to encode values as bytes for storage or transfer; this encoding is called serialization. Text represents text, while LongWritable and IntWritable wrap integer values. The four generic parameters below mean input key, input value, output key and output value, in that order.

Mapper generic parameterOur typeMeaning
Input keyLongWritableByte offset of the line
Input valueTextThe line itself
Output keyTextOne word
Output valueIntWritableThe emitted count, 1

Context is the object supplied by the framework for interacting with a task. Here, ctx.write(key, value) emits one output pair.

Reducer solution
Java
public static class SumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {
        private final IntWritable result = new IntWritable();

        @Override
        public void reduce(Text word, Iterable<IntWritable> counts, Context ctx)
                throws IOException, InterruptedException {
            int total = 0;
            for (IntWritable count : counts) {
                total += count.get();
            }
            result.set(total);
            ctx.write(word, result);
        }
    }

3. Configure and submit the job

Java · driver
public static void main(String[] args) throws Exception {
        if (args.length != 2) {
            System.err.println("Usage: WordCount <HDFS input> <HDFS output>");
            System.exit(2);
        }
        Configuration config = new Configuration();
        Job job = Job.getInstance(config, "week9-wordcount");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setReducerClass(SumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        job.setNumReduceTasks(1);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }

    public static class SumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {
        private final IntWritable result = new IntWritable();

        @Override
        public void reduce(Text word, Iterable<IntWritable> counts, Context ctx)
                throws IOException, InterruptedException {
            int total = 0;
            for (IntWritable count : counts) {
                total += count.get();
            }
            result.set(total);
            ctx.write(word, result);
        }
    }

    public static void main(String[] args) throws Exception {
        if (args.length != 2) {
            System.err.println("Usage: WordCount <HDFS input> <HDFS output>");
            System.exit(2);
        }
        Configuration config = new Configuration();
        Job job = Job.getInstance(config, "week9-wordcount");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setReducerClass(SumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        job.setNumReduceTasks(1);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

Limitations

MapReduce handles large batch jobs and retries eligible task failures, but job start-up, serialization, disk I/O and data exchange can be expensive. It is not designed for low-latency interactive queries. A chain of separate jobs may repeatedly read and write intermediate datasets.

Practise your knowledge

Conceptual questions

1. Why is a NameNode not a DataNode?

The NameNode maintains filesystem metadata and the block mapping; DataNodes store and serve the actual block bytes.

2. Why does one HDFS block not necessarily equal one map task?

Blocks are physical storage units; the InputFormat defines logical splits for map tasks.

3. What happens if a mapper fails?

Hadoop may schedule a new attempt. If the input remains readable, the work can be recomputed.

4. Why do equal keys have to reach the same reducer?

The reducer needs the complete group of values for a key to compute that key's aggregate correctly.

5. What does a replication factor of 1 demonstrate?

It supports the local one-DataNode lab, but does not provide redundancy across DataNodes.

6. What is the difference between HDFS and YARN?

HDFS is the distributed filesystem. YARN allocates resources and supports application execution.

Trace the whole system

Explain the recovery

The MapReduce ApplicationMaster coordinates a new attempt of the failed task. It obtains suitable container resources through the ResourceManager and asks a NodeManager to launch the process. The new attempt reads accessible HDFS input and recomputes its output. If no readable input replica remains, more retries cannot solve that missing-data problem.

Do three replicas imply three map tasks?

No. Replicas are alternative copies of the same stored bytes. The job's InputFormat defines its logical input splits; one map task is created per split. A higher replication factor does not by itself multiply the map task count.

Three map tasks exist, but only two are running. Is this an error?

Not necessarily. Available CPU and memory, queue policy and placement can limit how many tasks run concurrently. A pending task may begin when suitable resources become available.
