01 / HADOOP

Introduction

Apache Hadoop is an open-source software framework for storing and processing large datasets across a cluster (a group of connected computers that cooperate). Hadoop is the software; the cluster is the computing infrastructure on which its services and applications run.

Distributed storage

Split files into blocks and distribute those blocks across storage nodes.

Parallel computation

Several workers can process different portions of a dataset at the same time.

Fault tolerance

Keep redundant block copies and retry failed computation tasks.

Why use several computers?

A single machine has finite disk space, memory, CPU capacity and I/O bandwidth. When a dataset or processing workload outgrows that capacity, a cluster can distribute the work. Adding machines can increase capacity and throughput, but it also introduces network communication and coordination costs.

Two complementary kinds of fault tolerance

MechanismWhat it protectsExample
HDFS block replicationStored dataIf a DataNode fails, a surviving replica may still provide the block.
MapReduce task retriesComputationIf a mapper fails, Hadoop may run a new attempt using readable input.

Replication and retries solve different problems. Keeping a second copy of the data does not itself complete a failed computation; retrying a computation cannot recover data that has no readable copy.

Where Hadoop is useful

Hadoop is particularly suited to large batch workloads that scan and transform stored datasets: aggregating web logs, preparing historical data for analytics, or building derived reports. It is not an operational database designed to serve individual booking requests or perform low-latency record updates.

The Hadoop ecosystem

A real data platform is more than a storage system or a computation engine. It must collect data, retain it, execute processing, and make the results available. The Hadoop ecosystem refers to Hadoop's core modules together with separate tools that can complement them. An ecosystem is not a single executable, and a deployment does not need every related project.

03 / HADOOP

System architecture

Now that we know the platform roles, we can identify the services that implement them. A node is a participating machine or execution host; a daemon is a long-running service process. One machine may run several daemons, and a Hadoop application may launch temporary processes on different workers.

A typical multi-node cluster

The NameNode and ResourceManager are different control services. A NameNode knows where files are stored; it does not allocate CPU to a mapper. A ResourceManager decides resource allocations; it does not maintain the file block map. Each worker's DataNode serves stored bytes, and its NodeManager launches and monitors application containers.

Software, services and work are different levels

LevelExamplesMeaning
Hadoop moduleHDFS, YARN, MapReduceA functional part of the Hadoop software distribution.

Host / nodeWorker A, Worker BA machine or environment where processes run.
Application / jobWordCountOne submitted computation, coordinated by its ApplicationMaster.
Task attemptMapper or reducer attemptA specific execution of part of a job, inside a container.
YARN containerAllocated CPU and memoryExecution resources for a process; not necessarily a Docker container.

MapReduce defines and organises the job. It is not a fifth permanent daemon in our lab. Its ApplicationMaster and task attempts appear when the job runs. An optional JobHistoryServer can provide information about completed MapReduce jobs.

04 / HADOOP

HDFS

HDFS (Hadoop Distributed File System) stores large files as blocks. An application sees a normal file path, but the file's bytes may reside on different DataNodes.

ServiceWhat it manages
NameNodeThe filesystem namespace, file metadata, permissions and block locations.
DataNodeThe actual block contents on local disks; serves reads and writes.
ClientRequests metadata from the NameNode and transfers bytes directly with DataNodes.

Read a file

Write a file

The client requests file creation, then streams blocks through a DataNode pipeline selected by the NameNode. With multiple replicas, DataNodes forward data along the pipeline and acknowledgements travel back. Block reports and heartbeats help the NameNode track available nodes and blocks.

Replication

The replication factor defines the target number of copies per block. A factor of 2 means two replicas in total, not two additional copies. Different copies of the same block are placed on different DataNodes when possible.

If DataNode A fails, its blocks still have copies on B and C in this example. The NameNode can arrange replacement replicas when enough eligible storage is available. A one-DataNode lab cannot provide this redundancy. Replication does not protect against every failure or accidental deletion.

Block size versus actual data
A 300 MiB file with a nominal 128 MiB block size occupies blocks of 128, 128 and 44 MiB, excluding metadata and storage overhead. The final partial block does not require an entire 128 MiB disk allocation.
05 / HADOOP

YARN

YARN (Yet Another Resource Negotiator) allocates resources and manages application execution. It does not define the WordCount algorithm or store file blocks.

ComponentScopeRole
ResourceManagerClusterAllocates resources across applications.
NodeManagerWorker nodeLaunches and monitors containers and reports resource use.
ApplicationMasterOne applicationRequests containers and coordinates its own tasks.
ContainerAllocated resourcesExecution environment with resources such as memory and CPU.

Data locality

Reading a large block over a network can be expensive. When feasible, Hadoop schedules map tasks close to their input blocks. Locality is a scheduling preference, not a guarantee: a task may need to read remotely if suitable resources are unavailable.

Failure recovery

If a mapper process fails, the job can retry that task attempt. The retry is a computation mechanism, whereas HDFS replication is a storage mechanism. Retrying a task cannot recover missing input that has no readable replica.

MapReduce

MapReduce is a distributed batch-processing model. The programmer defines how to transform records into key–value pairs and how to combine the values belonging to each key. The framework manages input splits, scheduling, data exchange, sorting and task attempts.

Input splits versus HDFS blocks

A block is a physical storage unit. An InputSplit describes a logical portion of the input to be processed by a mapper. An InputFormat produces splits and supplies a record reader. The number of splits determines the number of map tasks; it need not equal the number of HDFS blocks. With text input, the default reader supplies a byte offset and a line of text.

Map

Each mapper receives records from its input split. It tokenises each line and emits (word, 1) for every word. It does not need access to the other mapper's input.

Shuffle and sort

The framework partitions mapper output by key so that all equal keys reach the same reducer. The reducer fetches intermediate partitions, and the framework sorts and groups keys. This transfer can involve network traffic and local disk I/O. In our one-reducer job, all keys are sent to that reducer.

Reduce

For each key, the reducer receives an iterable of values and sums them. With one reducer, our output is sorted by key within its single part file. With multiple reducers, output is partitioned into multiple part files; global order is not generally guaranteed.

spark[1, 1]2
Where is intermediate data stored?
Map outputs normally use worker-local intermediate storage and are fetched by reducers. They are not replicated in HDFS like input blocks. Lost map output may need to be recomputed. Final job output is written to the configured filesystem, HDFS in this lab.

A Hadoop MapReduce program has a Mapper, a Reducer and a Driver. The Mapper and Reducer define the computation. The Driver describes the job to Hadoop and submits it.

Reducer solution
Java
public static class SumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {
        private final IntWritable result = new IntWritable();

        @Override
        public void reduce(Text word, Iterable<IntWritable> counts, Context ctx)
                throws IOException, InterruptedException {
            int total = 0;
            for (IntWritable count : counts) {
                total += count.get();
            }
            result.set(total);
            ctx.write(word, result);
        }
    }

import java.io.IOException;
import java.util.StringTokenizer;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.Mapper;
import org.apache.hadoop.mapreduce.Reducer;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class WordCount {
    public static class TokenizerMapper
            extends Mapper<LongWritable, Text, Text, IntWritable> {
        private static final IntWritable ONE = new IntWritable(1);
        private final Text word = new Text();

        @Override
        public void map(LongWritable offset, Text line, Context ctx)
                throws IOException, InterruptedException {
            StringTokenizer tokens = new StringTokenizer(line.toString());
            while (tokens.hasMoreTokens()) {
                word.set(tokens.nextToken());
                ctx.write(word, ONE);
            }
        }
    }

    public static class SumReducer
            extends Reducer<Text, IntWritable, Text, IntWritable> {
        private final IntWritable result = new IntWritable();

        @Override
        public void reduce(Text word, Iterable<IntWritable> counts, Context ctx)
                throws IOException, InterruptedException {
            int total = 0;
            for (IntWritable count : counts) {
                total += count.get();
            }
            result.set(total);
            ctx.write(word, result);
        }
    }

    public static void main(String[] args) throws Exception {
        if (args.length != 2) {
            System.err.println("Usage: WordCount <HDFS input> <HDFS output>");
            System.exit(2);
        }
        Configuration config = new Configuration();
        Job job = Job.getInstance(config, "week9-wordcount");
        job.setJarByClass(WordCount.class);
        job.setMapperClass(TokenizerMapper.class);
        job.setReducerClass(SumReducer.class);
        job.setOutputKeyClass(Text.class);
        job.setOutputValueClass(IntWritable.class);
        job.setNumReduceTasks(1);
        FileInputFormat.addInputPath(job, new Path(args[0]));
        FileOutputFormat.setOutputPath(job, new Path(args[1]));
        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}

Limitations

MapReduce handles large batch jobs and retries eligible task failures, but job start-up, serialization, disk I/O and data exchange can be expensive. It is not designed for low-latency interactive queries. A chain of separate jobs may repeatedly read and write intermediate datasets.

Practise your knowledge

Conceptual questions

1. Why is a NameNode not a DataNode?

The NameNode maintains filesystem metadata and the block mapping; DataNodes store and serve the actual block bytes.

2. Why does one HDFS block not necessarily equal one map task?

Blocks are physical storage units; the InputFormat defines logical splits for map tasks.

3. What happens if a mapper fails?

Hadoop may schedule a new attempt. If the input remains readable, the work can be recomputed.

4. Why do equal keys have to reach the same reducer?

The reducer needs the complete group of values for a key to compute that key's aggregate correctly.

5. What does a replication factor of 1 demonstrate?

It supports the local one-DataNode lab, but does not provide redundancy across DataNodes.

6. What is the difference between HDFS and YARN?

HDFS is the distributed filesystem. YARN allocates resources and supports application execution.

Extend the program

Modify the Mapper to normalise words to lowercase, filter out empty tokens, and count only words of length at least four. Run the modified job using a new HDFS output path. Explain how the output differs and why the Reducer can remain unchanged.
